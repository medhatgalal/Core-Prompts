# Skill Job Map

This is a plain-English routing map, not behavioral proof and not a merger plan. The canonical behavior remains in `ssot/`.

Portfolio actions mean:

- `keep`: the boundary is already focused.
- `keep_and_clarify_boundary`: preserve the skill and sharpen how it differs from neighbors.
- `keep_but_review_scope`: preserve it, then test whether its Swiss-army or advisory scope is too broad.
- `experimental_keep_pending_evidence`: keep the experiment separate until routing and preservation evidence exists.
- `keep_and_improve_process`: preserve the capability and improve its evidence or workflow controls.
- `draft_new_skill_pending_review`: UAC created a safe placeholder; a human must review its job and neighbors.

No skill is marked for merger or deletion because current evidence does not justify either action.

## Routing Questions

- `engos-delivery-address-code-review`: Are we finding problems, or applying already-selected review feedback?
- `engos-memory-context-continuity`: Does the investigation need resumable reasoning state rather than a one-time report?
- `engos-design-architecture`: Is the deliverable a technical design, or merely a recommendation among existing options?
- `engos-optimization-auto-research`: Do we need evidence of better behavior, or only a stronger draft?
- `engos-quality-code-review`: Are we reviewing code for defects, applying feedback, or checking release mechanics?
- `engos-audit-code-health`: Is the question about code structure, product completeness, or delivery activity?
- `engos-reconciliation-converge`: Are there multiple competing inputs that must become one decision?
- `engos-browser-demo-recorder`: Is the browser flow meant to prove behavior or communicate it as a demo?
- `engos-quality-docs-review`: Is the problem document-system health or sentence-level instruction editing?
- `engos-content-dynamic-html-presentations`: Is the main artifact a deck, a live product demo, or a written report?
- `engos-audit-engineering-progress`: Is the question about engineering activity, product completeness, or code health?
- `engos-audit-feature-status`: Are we asking whether the product feature is complete, how the repo is structured, or what activity occurred?
- `engos-quality-gitops-review`: Is the blocker in code correctness or in the path from repo state to release?
- `engos-operations-ic-assistant`: Is there an active incident with a commander and a required process?
- `engos-meta-instruction-editor`: Is the goal clearer language, a stronger artifact, or proof that behavior improved?
- `engos-audit-pitch-review`: Is this a future investment pitch, a current feature status check, or a general decision synthesis?
- `engos-triage-my-inbox-chat-pulse`: Is this personal communications triage, incident process, or a periodic intelligence report?
- `engos-delivery-resolve-conflict`: Is there an actual merge conflict to resolve, or merely disagreement among proposals?
- `engos-meta-supercharge`: Does the user want the artifact strengthened, or evidence that one strengthened variant performs best?
- `engos-quality-testing-review`: Is the main task to test behavior, review code, or prove release readiness?
- `engos-memory-threader`: Are we exporting the conversation, or maintaining an ongoing evidence investigation?
- `engos-meta-uac-import`: Are we importing a capability, editing instructions, or proving behavior?
- `engos-audit-weekly-intel`: Is the report multi-source and executive, repo-activity focused, or about one feature's completeness?
- `engos-orchestration-batman`: Does this authorized repository change require subagent-driven implementation with blocking review backpressure and evidence through landing?
- `engos-design-plan-to-goal`: Does this request directly require Plan to Goal Design?
- `engos-audit-opex-incident-review`: Does this request require a stateful Operational Excellence incident-estate audit and Daily OpEx Digest?
- `loopy`: Does this request directly require Loopy — Bounded Agent Loops?
