## What it is for

Meeting notes written by Gemini carry decisions, action items with owners, attendees and what was discussed. The adapter will do two jobs.

1. Capture: action items assigned to the user, and follow-ups the user promised. One item per action, linked to the note and its meeting.
2. Context: supply background to clarify, reflect and engage. For example, link a note to an existing task or project, or show what was decided last time before the user plans.

## What is not verified

- Which Drive files are Gemini meeting notes, and how to find them.
- How a note maps to a calendar event.
- What action-item text looks like, and how owners are named.
- Window, source-key format and tags.

## Discovery checklist for the owner to approve

No commands are given. Before any command is run, the owner approves each step.

1. Pick three recent meetings the user attended that had notes. Name them.
2. Find where those notes live (folder, owner, naming) by hand in the Drive interface.
3. Record: file type, title pattern, whether the notes link to the calendar event, and whether the event links to the notes.
4. Copy three real action-item passages (redact names if needed) to show how owners and tasks are written.
5. Decide, with the owner, which of the two jobs to build first.
6. Draft become-a-task rules and a source key from those samples. The owner approves them. Only then write commands.

Until step 6 is approved, this source reports "not built" in the run report.
