# Publication dispatch

Preflight target capability/read access early, but publish accepted content only
after current G3. Resolve the embed helper and target resources; read runtime.md
and helper help at actual invocation for documented delivery operations. Record
delivery intent before writing, bound to run, approved bundle hash, surface,
account, destination and unique operation ID. Never infer sharing authority.

Use `dispatch.md`, replacing only its publication prohibition with the following
target-scoped prompt when the work order actually grants that authority:

> Act as publisher for the named account and destination only. Read the approved
> bundle, full inventories, target authority/revision and adapter resources.
> Transform representation without changing meaning. Preserve complete prose,
> every table row, all three diagrams, captions, evidence, exclusions and status.
> Follow the registered delivery intent, write using supported guarded operations,
> then read back the actual saved target and perform representation-specific
> verification: inspect saved pixels for visual targets, or parse and compare
> full structured content for JSON. Never invent pixels for a nonvisual target. Return
> target identity/revision, source hash, inventory comparison, observations and
> discrepancies. Stop on policy denial or concurrent target edits. If write success
> is uncertain, reconcile the existing operation before retrying; do not create
> another target blindly. Do not redesign, share, accept state or approve a bet.

Submit actual saved results for G4 through the gate owner. Required receipt fields
include operation/target identity, source and target revisions, representation,
full content/row/diagram comparison, applicable style/visual observations (or JSON
parse and structured-parity evidence), readback evidence,
limitations, status, owner and next action. An upload acknowledgement is not proof.

Follow the gate owner's representation-specific G4 policy. This does not waive
G3's local diagram render inspection or saved-target pixels for HTML and Docs.

Content pass and target delivery are separate statuses. Failed access or rendering
holds that target/G4 while preserving unchanged G3. Zero targets cannot imply a
delivery pass. An explicit frame-only or draft-only endpoint needs no pretend G4.
When HTML and Google Docs are both required, one passing target cannot stand in
for the other. Keep an external operation pending if its target cannot be uniquely
identified; report `reconciliation_required`. No exactly-once guarantee is claimed
for a remote API without that mechanism. See `representations.md` for full fidelity.
