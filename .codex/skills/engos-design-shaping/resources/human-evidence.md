# Human-led evidence and teammate returns

Draft a card, not a demand that the user invent a test plan. Keep one card per
blocking question or tightly related decision. The initiating user can share it;
do not message teammates, grant access or broaden recipients automatically.
Include only extracts permitted for that recipient and destination.

The card is a record template, not a questionnaire to send with every field blank.
Fill known metadata and keep the actual requested actions within the same one-to-three
question budget, counting distinct subrequests. Prefer forwarding one existing
permitted artifact over asking a novice to reconstruct six incident facts. Stage
additional owner or preference questions rather than burying them in the message.

## Evidence request card template

- Run / stage / accepted revision / generation / card ID:
- Question and uncertainty IDs; decision affected; why this changes the bet:
- Known evidence and exact coverage gap:
- Proposed hypothesis, explicitly not a finding:
- Smallest requested files/spec sections/screenshots or experiment result:
- Suggested safe inspection steps and authorized environment; unknown locations
  marked as suggestions; no production execution implied:
- Expected respondent/expertise; confirmed owner or owner_unassigned:
- Effort bound and stop condition:
- Pass/fail/insufficient signal, set before collection:
- Return format: claim/answer, source/revision/scope, method, actual result,
  limitations, attributable respondent, date, safe artifact reference:
- If unavailable: smaller permitted extract, alternate evidence or scope option:

## Teammate question/decision card template

- Run / stage / revision / current decision and deadline or effort checkpoint:
- Short orientation: understood problem, settled facts and what changed:
- Relevant permitted source extracts with IDs/revisions:
- Question/uncertainty and why the decision matters:
- Proposed answer/options, clearly labeled, with consequences and evidence:
- Current dissent or conflicting/relayed answers:
- Expected respondent and authority needed:
- Return choices: answer; challenge; attach evidence; nominate another owner:
- Response attribution and whether direct or relayed:
- Next action after return; no implicit approval from silence:

On return, verify card/run/revision and respondent, compare with accepted inputs,
record candidate events and show orientation before asking further questions.
Retain conflicting current answers as disputed. Product authority can settle
trade-offs; engineering assertions remain opinion unless backed by the required
observation. An independently designated private-evidence reviewer can supply the
assessment described in `sources.md`; never label it AI-verified. Reconcile with
the same evidence standard as AI acquisition and reopen only affected stages.
