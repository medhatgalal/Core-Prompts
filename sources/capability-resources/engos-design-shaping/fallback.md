# Manual capability fallback

Record the unavailable capability, affected phase, actual error/limitation and
smallest next action. Continue independent work within existing authority. A
fallback changes the means of collection or presentation, not the evidence bar.

| Missing capability | Useful manual path | State that remains pending |
| --- | --- | --- |
| Source extraction/access | Ask for approved text/pages or a precise redacted extract; retain coverage limits | Dependent claim verification |
| Repository tools/access | Use the human-evidence route and transferable request card | Research until sufficient evidence returns |
| Generic independent worker | Designated independent human with source access and attributable revision-bound review | Review until actual assessment; conductor self-audit is insufficient |
| Safe context isolation | Use an authorized suitable host or permitted redacted extract | Restricted dispatch; no confidentiality claim from prompts |
| Gate package/integration/calibration | Resolve the actual bound resource through registry/controller | Gate review; unaccepted draft preparation may continue |
| Runtime helper/documented interface | Preserve candidate files and a human-readable handoff with IDs/hashes; ask controller to restore compatible helper | Mechanical acceptance/recovery; do not edit accepted pointer by hand or claim CAS/replay proof |
| Diagram renderer/visual inspection | Retain source and ask an authorized operator for actual render and observations | Render-dependent review |
| Target write/convert capability | Supply approved source/exports and exact private manual placement/readback steps | Delivery/G4 until saved result is inspected |
| External revision/base identity | Recover registered base/target evidence; preserve edits | Reconciliation; no blind overwrite or duplicate |

Manual completion requires actual evidence under the same current gate contract.
If a required predicate cannot be assessed, report unverifiable with owner/action.
No silent gate waiver, tool-switching to evade policy denial, automatic sharing,
new OAuth scopes, native agent installation or simulated human approval. Do not
teach a run-specific error as a standing policy rule.
