# Reader-first diagrams and contracts

Inspect rendered references as well as source structure before matching a house
style. Record the reference/revision and visual criteria; do not copy unsupported
facts, invented owners or a readiness label from a sample. Rich formatting clarifies
the argument, not a substitute for framing, research or independent review.

For Framed documents, preserve a clear problem/scenario, why-now, appetite/walk-away,
boundaries and questions. Do not add architecture merely to make the page visual.
For Shaped documents, place component, sequence and data-flow figures beside their
explanations, with a visible title, caption, legend, state labels and intentional
omissions. Use explicit source/section anchors, not a disconnected image appendix.

Keep Mermaid as the preferred editable source. For a selected rich presentation
profile, render the requested source-bound SVG/PNG derivatives. An explicit
multi-surface request for both authorizes both; otherwise create PNG only when
the requested surface needs it. Native-Mermaid-only requests need no image step.
If Mermaid cannot produce a readable fat-marker layout, a curated SVG is permissible
with a recorded layout reason, source identity and semantic cross-check of every
component/seam; retain editable source. Use SVG for HTML/full-size viewing and
high-resolution PNG for Docs. A renderer/format change cannot invent internals.
Only use the embed adapter's validated asset path; arbitrary SVG is untrusted.

Primary tables should be readable at normal viewing size. Preserve Method/Purpose
or Method/Endpoint/Purpose and Responsibility/Owner/How-enforced shapes. For wide
contracts, present a compact primary table and link all detailed fields through
stable row IDs. Enumerate every original field and compare converted values; never
drop columns silently, hide unknown owners, or use table screenshots instead of
native cells. Put long explanatory prose in supporting sections, not squeezed cells.

Apply consistent hierarchy, generous spacing and the specified semantic palette.
State colors also need explicit text; proposed/unknown/needs-spike must not look
like verified acceptance. Preserve uncertainty, source citations, list nesting,
emphasis and code without literal formatting debris. Avoid oversized graph strips,
tiny labels, split row content and orphan captions; repeated table headers should
remain visible across document pages.

Use the embed adapter's current presentation/export resource for actual schema,
profiles and commands. Maintain source/asset hashes and keep visual/placement
observations outside source content. Parser success, table counts and a clean
browser console do not establish readability. Authoring/G3 inspects local rendered
figures and source presentation. The publisher/G4 later inspects every authorized
saved target, including narrow/wide HTML and saved document pages; target inspection
is not a prerequisite for authoring or a grant of publication authority.
