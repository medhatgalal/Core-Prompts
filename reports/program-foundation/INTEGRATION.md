# Reviewed skill foundation

This candidate combines eight previously reviewed slices from the same main
revision. It preserves their original commits, all nine canonical skill bodies,
authored resource bytes and baseline lineage. Four additions bring the inventory
from 32 to 36 skills, with 180 provider packages and no named agents.

The additions are `engos-design-specify-change`,
`engos-design-plan-implementation`, `engos-debug-diagnose-failure` and
`engos-delivery-implement-slice`. Existing authoring, instruction editing, code
review, test design and architecture skills retain their current names.

The combined generator and UAC path use current source declarations for mode
membership, locations and invocation hints. Matching descriptive curation remains
available; removed modes cannot reappear through old metadata. Shared resources
retain their authored owner, including the specification schema bundled into
architecture without an installed sibling dependency. The implementation worker
role and both CI resource-test lists survive composition.

Integration exposed and repaired a stale 33-skill assertion/public inventory and
an architecture topology that omitted its four current source modes. Generated
status timestamps also refreshed. Original failures remain in the local CI
receipts; they are not represented as successful checks.

## Evidence and limits

`LOCAL-VALIDATION.json` records all 13 GitLab-aligned checks: 1,297 passed, one
skip and 16 passed subtests. The local sequence resumed at compilation after the
derived topology refresh, retaining eight checks against unchanged authored and
executable sources. Four focused topology checks and the exact skills-only count
assertion passed. Hosted CI must run the full suite on the final commit.

`product-payload.json` binds the 438 changed product files. The independent
composition review and mode review retain findings, repairs, hashes and their
separate acceptance scopes. These checks establish source and package integrity;
they do not establish comparative model quality or native-provider behavior.

This foundation does not complete the whole implementation program. Later
collectors, graph/trace tools, documentation recipes, skill handoffs, adoption
fixtures and native-provider checks remain separate work. Release, tag, live
installation, exact skill retirement and registered agent changes are outside
this candidate.
