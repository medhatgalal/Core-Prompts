## Follow-up execution trial on November 11

Two fresh Codex builders received identical local Python fixtures and the request “Our weekly report counts duplicate open tickets. Fix the count and give me the one-sentence release note. Keep this a verified local change.” Birch received that request directly. Amber received it inside the linked everyday prompt. Both used the same model and low effort, the same available skills, one directory each and a verifier supplied by the controller. The verifier froze the criteria and ran the controls before dispatch. It then inspected the actual submissions without the treatment labels or builder verdicts.

| One point per criterion fixed before dispatch | Direct request | Everyday prompt |
| --- | --- | --- |
| All six hidden count cases pass | 1 | 1 |
| Added visible duplicate test passes on fix and fails on original | 1 | 1 |
| Truthful one-sentence release note | 1 | 1 |
| Exact local scope verified from files and builder operation record | 0 | 0 |
| Total | 3/4 | 3/4 |

The oracle covered empty/all-closed input, duplicate opens, both open/closed orderings for one ID, distinct IDs and a mixed-state generator. Before dispatch it rejected the original on duplicate opens and the generator, accepted a known good implementation, and rejected a deduplicate-before-filter mutant on closed-then-open and the generator. Both builders returned the same implementation (SHA-256 `e03fe37965507799a33630d9a00ea933de0f424bacbc3d991710e561c040dd16`). The verifier reran four visible tests per arm and reproduced `3 != 2` with each new duplicate test on the original. Birch’s release note was “Weekly reports now count each open ticket once, even when duplicate records are present.” Amber’s was “Fixed weekly reports to count each open ticket once, even when duplicate records exist.” Both directories contained only source and tests. The verifier lacked complete operation records, so it withheld the scope point in both arms.

This supervised Codex trial demonstrated the handoff from an ordinary request to a tested patch and an independent check. It tied under the frozen strict-win rule. It supplies no measured advantage for wrapping a small fix in the longer prompt. Skill use was available to both arms; native skill auto-selection, filesystem isolation, repeated-trial reliability, and other hosts were unmeasured.

## What Scott added and when to use it

Scott Parrish introduced Crew in `3cbc8344` and added the user handoff and KiroCrew adapter in `5ed1eeeb`. Both are present in the experiment baseline `cfb7f03b`. Crew adds a designer, lead, workers, fresh verifiers, safety watch and drift auditor to a long-running job with frozen criteria. The KiroCrew adapter was documented from source. Its launch was unverified.

| Desired result | Skill and handoff |
| --- | --- |
| Clearer prompt or grading rubric | Supercharge can simplify, critique or grade the actual text. Finish with the requested edit or applied rubric. |
| Definition of a vague problem | Route Intent finds the first missing result. Frame from Vague establishes the problem, evidence and open questions. Shaping develops an accepted frame into a reviewed proposal. The user supplies appetite and investment decisions. |
| Choice between plausible solutions | Auto-Research measures alternatives on matched inputs. Converge resolves competing evidence when it supports a choice. Preserve ties and failed trials. |
| Repeatable loop or inactive goal | Loopy defines observations, feedback, retries and stopping conditions. Plan-to-Goal turns an accepted plan into milestones and a verifier. Leave a prepared goal inactive until launch is requested. |
| Reviewed implementation | An audit or diagnosis supplies evidence if it can change the plan. Implement Slice builds accepted work. Code and testing reviews examine the exact change. Address the findings and send repairs back for independent verification. When efficiency is an objective, measure it against the same correctness checks. |
| Verified landing or sustained multi-agent work | Batman owns its explicitly requested gated delivery protocol. Crew owns long jobs requiring fixed criteria, role independence and qualified supervision. Its unattended preflight requires 60 consecutive ten-minute lead responses, or ten hours before production. |
| Progress and open issues | Engineering Progress covers Git activity. Weekly Intel joins current tracker and repository evidence and calls for independent review of a substantial report. |

Use the host features observed in the current session. A native workflow can schedule stages only when the host exposes that facility and its steps actually return the required artifacts. A foreground worker can build or verify a bounded result. Unattended work needs separate evidence that the lead wakes and acts without human intervention.
