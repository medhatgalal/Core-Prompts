# Design freshness / upstream merge conflict analysis

## Inversion Analysis

This merge would fail if it discarded the freshness capability or its required gates, lost either incoming skill, represented stale generated metadata as the union, or turned upstream release history into a claim that freshness was released. Success requires additive canonical content, regenerated outputs, preserved release provenance, and verification before committing.

## Conflict Summary

Inspection of `git diff --name-only --diff-filter=U` found eight conflicted paths: `CHANGELOG.md`, `README.md`, `.meta/install-bundle.json`, `.meta/skill-job-map.json`, `docs/CAPABILITY-CATALOG.md`, `docs/RELEASE-DELTA.md`, `docs/STATUS.md`, and `docs/guide/index.html`.

No instruction-body conflict is reported by Git. This artifact records a proposed resolution; it does not claim that resolution or verification has occurred.

## Resolution Strategy

Keep HEAD's complete `Unreleased` freshness section, followed by incoming's complete v1.22.0 section and existing older history. Set README's count to 46 only after the generated union confirms 43 base skills plus two incoming skills plus freshness. Preserve incoming `VERSION`, both incoming canonical skill bodies, metadata, assets and evaluations unchanged. Preserve freshness source and its gate integrations.

Reseed the six conflicted generated files from incoming bytes solely to provide readable build inputs, then regenerate them from the union of canonical sources. Incoming generated bytes are temporary inputs, not the lasting resolution. Do not hand-patch generated metadata or catalogs to manufacture agreement.

Before building, refresh the canonical router inventory snapshot at `sources/capability-resources/engos-route-intent/routing-relations.json` with inventory summaries and hashes for exactly the two incoming descriptors, comms-digest and jira-intake-review. Retain all prior inventory entries and all 24 existing relationship semantics. The normal build does not refresh this canonical snapshot; rebuilding alone cannot repair its missing entries.

2. Resolve the two handwritten conflicts as above, retaining automatically merged additions.
3. Refresh the canonical router inventory for exactly the two incoming descriptors as described above, preserving prior entries and relationship semantics. Add or run a direct source-catalog set-equality check against all descriptor identities.
