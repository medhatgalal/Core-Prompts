# v1.16.5 — Shaping acceptance and handover

Shaping now asks for engineering frame agreement, team package acceptance and the betting-table decision separately. Accept writes one handover with every build item and proof, deferred items and reasons, and forbidden work. A separate build session starts at spec for that included list; proceed and loop cannot drop or add scope.

After writing the handover, the person chooses HTML, Google Doc, Word, JSON or all four. Only selected outputs are produced, using the existing diagrams and export paths. Word is handover-only through the host document skill. Shaping writes no downstream spec, requirements, design, architecture, plan or tasks.

The installer recognizes the three existing shaping-package identities from the verified v1.16.4 release, allowing pristine packages with older ownership records to upgrade. Modified files, modes and extra user files remain protected. No new capability or agent surface is added.

This release has instruction-preservation, structural and regression evidence. It does not claim a successful live shaping/build exercise or real Google Doc placement. Existing runs retain their pinned policy; installation does not migrate them automatically.
