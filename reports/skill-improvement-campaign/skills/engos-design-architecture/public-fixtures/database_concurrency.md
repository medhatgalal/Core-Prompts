Design storage for project-local document IDs in a multi-tenant relational application using PostgreSQL 18. A document ID is unique within its tenant; an annotation must reference a document in the same tenant. Two concurrent requests may create the same document ID. Required queries list a tenant’s newest documents by created_at with document_id as tie-breaker and retrieve annotations by tenant/document. Deleting a document with annotations must fail until annotations are explicitly handled. Design keys, constraints, transaction/conflict handling, indexes, retention/recovery questions and validation. Do not run SQL. Current schema has globally unique document_id with existing rows; tenant-local duplicates must eventually be allowed.
