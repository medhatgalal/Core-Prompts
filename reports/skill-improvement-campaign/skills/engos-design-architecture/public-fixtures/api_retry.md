Design an internal tenant-scoped job submission API. Clients can retry after 30-second network timeouts for up to 24 hours. A worker performs a billable extraction; the same client operation must not bill twice. Tenants may reuse the same client key. Concurrent same-key submissions and different payloads using the same key occur. The effect is committed in the same database as job state, but responses may be lost. Clients need submission and polling, errors, pagination and an upgrade path from the existing unkeyed v1 endpoint. Current consumers cannot all upgrade on the same day. Produce a design, a compact operation catalog, request/success/error examples and validation cases. Do not implement or execute it.
