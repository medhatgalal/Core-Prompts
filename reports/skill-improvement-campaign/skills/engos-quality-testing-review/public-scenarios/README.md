# Broader PUBLIC development cases

All tasks, answers and faults here are public authored development examples.
`cases.json` maps twelve cases across six major jobs and three routing/authority
controls. They are not independently held out, representative production data,
or proof that any model/skill improves. `public-answers.json` is deliberately public
and must never be labeled a sealed evaluator asset.

The previous `../public-fixtures/` lease/retry examples remain unchanged.
Additional trusted checks cover a real local SQLite persistence boundary, a
Python behavior gap despite measured coverage, JavaScript framework fit, and
checkout markup/syntax. Browser E2E is **not executed** by this pack.

```sh
python3 reports/skill-improvement-campaign/skills/engos-quality-testing-review/public-scenarios/check_scenarios.py
```

The checker uses standard runners for fixed author-controlled code only. It does
not accept generated submissions, award skill scores, provide containment for
untrusted code, or replace capability-eval. A later evaluator must execute emitted
tests in the coordinator's admitted boundary. The author intentionally executes
these public development controls; a target-skill producer must truthfully leave
its generated tests unrun.

Case exports must include only the listed public input files, preserving a declared
mini-repository layout. They must not copy this whole folder into a bare arm:
public answers and example suites are accessible here. Ordinary test collection
from the whole campaign directory is not supported; use the fixed checker.
