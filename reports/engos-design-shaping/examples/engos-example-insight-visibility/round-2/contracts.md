No new storage, queue, retry service, metric algorithm or pseudonymization method is asserted as existing or required.

## Exact acceptance expectations — proposed, unexecuted

| ID | Given / action | Expected evidence |
| --- | --- | --- |
| A1 | Existing S1-compatible account/day record with counts v and g, after activation | Submitted payload contains only the four S1 fields, preserving pseudonymous ID, UTC day, v and g exactly. Permitted PM sees those values |
| A2 | Send the same record twice, then corrected counts for the same key | One platform account/day record, no addition/double count. Corrected values replace previous values. No claim about concurrent writers |
| A3 | Source candidate includes document text or prompt | Proposed allowlist prevents that data crossing. Only S1-compatible projection may be submitted; if it cannot be formed, withhold and expose failure |
| A4 | Source read denied or reporting user lacks existing PM role | No publication from denied read; no metric disclosure to unauthorized reporting user. Credentials never enter payload |
| A5 | Intake failure, uncertain result or insufficient quota | Publication remains incomplete; no blind unbounded replay. Reconcile current retained source record before a bounded same-key rerun. Accepted previous records are not rolled back or claimed missing |
| A6 | Source record absent or expired, or requested day predates activation | Do not fabricate zero. Mark unavailable/incomplete where applicable; do not silently backfill pre-activation history |

v/g are symbolic future checks, not manufactured measured counts. A1–A3 derive from `input.md:9-13` and `round-two-clarifications.md:27-31`; A4 from clarification lines 29–30; A5/A6 are proposed responses to constraints in `round-two-clarifications.md:28-34`.
