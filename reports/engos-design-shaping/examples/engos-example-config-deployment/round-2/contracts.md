## Complete presence/value cases

Each successful import also requires authorization, compatibility, override and commit checks. Cost no-op does not mean skip the rest of a valid process deployment. This table supplies no deletion behavior.

| Case ID | Source/package state | Required outcome | Provenance |
| --- | --- | --- | --- |
| V1 | Successful source read finds no cost configuration; old package omits section | Export may truthfully represent absence. Import preserves target currency AND activities. | `input.md:24-25`, `round-two-clarifications.md:58-60` |
| V2 | Present empty cost/activity list without a currency update | Valid no-op for target costs, not malformed and not deletion. | `round-two-clarifications.md:38-41`, `round-two-clarifications.md:58-59` |
| V3 | Valid currency only, activities omitted or explicitly empty | Update supplied currency, preserve all target activity entries. | `round-two-clarifications.md:57-59` |
| V4 | Valid nonempty activity definitions, with supplied valid currency if present | Add/update supplied definitions in their UUID association; preserve omitted and unrelated settings. Zero and positive costs both valid. No removal by omission. | `input.md:22`, `round-two-clarifications.md:38-40`, `round-two-clarifications.md:47-48`, `round-two-clarifications.md:57-59` |
| V5 | Malformed data, negative activity cost or unsupported currency | Validation failure, no partial package mutation. Absence/empty cannot be used as a fallback. | `input.md:26-27`, `round-two-clarifications.md:47-48`, `round-two-clarifications.md:60-62` |
| V6 | Source read fails | Abort export, do not create a successful package claiming absence or empty. | `round-two-clarifications.md:59-60` |
