# engos-design-shaping gap analysis

The primary failure was loss of process ownership. A rough note went directly
into solution prose; later formatting work could not restore missing decisions
or evidence. Adding diagrams improves the output but cannot establish that the
problem was framed, the appetite chosen, or the solution researched.

| Failure | Missing rail | Stage and required correction | Shape Up grounding |
| --- | --- | --- | --- |
| Framing assembled inside freeform chat | Durable frame and advancement condition | 0→1: preserve input, distinguish facts/assumptions/missing information, write a solution-free frame | Set boundaries |
| Solution started before framing decisions | Explicit boundary between framing and design | 1: appetite, walk-away, boundaries and open questions must pass before research-led solutioning | Fixed time, variable scope |
| Invented top risk | Evidence and risk provenance | 2: question IDs, opened source paths/lines or observed spike results, named uncertainty and mitigation | Remove rabbit holes |
| Existing shaper never engaged | One discoverable process owner | Conductor owns progress and loads phase skills/resources; fails closed if a required part is unavailable | Shaping before betting |
| Repeated human rejection | Independent gate and exemplified rubric | 3: measure all exemplar elements plus team/pitch rubrics; correct weakest dimension with recorded before/after observations | Rough, solved, bounded |
| Multi-hour formatting fight | Surface preflight and source-preserving placement | 3→4: render once, retain source, use supported adapter; verify actual saved content and pixels | Appetite discipline |
| Complete declared from file existence | Actual gate execution and placement proof | 4: current pass receipts for every stage plus correct target placement; an explicit human step stays incomplete | Bet readiness differs from a bet |

The reusable change is a conductor and phase/gate contracts around the existing
research/artifact/review responsibilities. Upstream's shaper is the behavioral
starting point; Core-Prompts is the portable authoring/distribution authority.
The diagram and embed helpers become subordinate stage-3/4 tools. The independent
pitch reviewer consumes the same gate contract instead of maintaining a competing
checklist. Full delivery artifacts include framing, decisions, research, pitch,
workstreams, proof slices, journal, traceability and betting preparation.

Budget failures retain the last passing stage and a concrete next action. A
named spike cannot be relabeled resolved. An excluded requirement requires an
actual scope decision, not automatic deletion to obtain a pass. A human bet,
production code, Jira tickets, release and installation remain outside this
design-and-exercise task.
