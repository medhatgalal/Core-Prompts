# Authoring decisions

Owner: `engos-meta-uac-import`. Load before drafting a capability addition or material update. This is the selected portable authoring method; it does not add another router or control the invoking host.

## Select the smallest useful change

Compare the requested outcome and triggers with current SSOT clauses and resources before choosing:

| Choice | Use when | Required decision |
| --- | --- | --- |
| `reuse` | An existing capability already covers the outcome | Name that owner and clause; explain why no new obligation is needed |
| `harvest` | A source contains a missing, compatible instruction | Name one receiving owner, the source passage, destination, and any displaced clause |
| `combine` | Compatible source ideas serve one existing job | Resolve overlaps and conflicting conditions into one owned instruction; preserve distinct independently callable jobs |
| `new` | No current owner covers the user outcome | Show the gap and precise positive/negative trigger; default to a skill within authorized scope |

A selected choice does not authorize a rename, retirement, new named agent, or installation. Keep existing identities and surface scope for same-owner improvements. A `combine` decision is not permission to merge distinct skills.

## Place facts and mechanics

Keep each operative fact at one authoritative source. Search the current owner before adding text, repair that location, and link to it for optional detail. Generated provider copies are intentional outputs, not additional authored owners. Keep essential outcome, triggers, inputs, outputs, and authority readable in the entrypoint. Declare every packaged dependency in the owner's resource map, with route conditions that say when it must be loaded. Do not depend on a sibling installed skill's private files.

Reuse an existing CLI or helper when its actual help and behavior meet the need. Document a missing contract before proposing new code. Retain the existing instruction-clarity policy as the authority for editorial rules; this method does not restate it. Host settings, workspace/global precedence, tools, scheduling, and permissions remain with the host.

## Record source admission and preservation

Complete `resources/templates/preservation-displacement.json` for the candidate. For each selected external donor, record origin, exact revision or `unknown`, inspected body SHA-256, selected resource hashes, applicable license/notice scope, dependency closure, host/tool compatibility, receiving owner, and reuse decision before borrowing.

Distinguish independently expressed pattern synthesis from literal or substantial text, template, script, or asset reuse. Unknown rights do not authorize literal/substantial copying; leave that harvest unresolved or use an independently written, attributed pattern with the evidence limit recorded. A source hash is identity evidence, not permission. Inspect license scope for the specific file/resource; do not extend a creator-local or repository-specific license to an entire collection.

Map every operative original clause to its destination and disposition. Preserve exact commands, conditions, modality, authority, prerequisites, ordering, schemas, output contracts, examples, exceptions, and fallbacks. Name displaced content; distinguish preserved wording, exact relocation, reviewed reformulation, and explicitly authorized retirement. Unknown or ambiguous meaning remains unresolved. Bind source and candidate hashes and inventory affected consumers, including unknown external consumers. The template is an authoring record, not independent semantic approval.

## Match evidence to the claim

| Change or claim | Evidence to obtain |
| --- | --- |
| Exact relocation or low-risk contract-neutral wording | Source/destination comparison including scope and exceptions, diff, link/parse checks and preservation map |
| Material instruction change | Explicit intent, complete dispositions, independently reviewed exact candidate and effective resources, then existing UAC admission gates |
| Helper, parser, generator, or resource-loading behavior changes | Focused success/failure tests for the affected behavior, plus package closure and UAC/surface checks |
| Claimed behavioral benefit | Bounded baseline comparison through `engos-optimization-auto-research`, trigger-positive/negative and resource-dependent cases where relevant, independent grading and human inspection of resulting artifacts |

Do not launch a paid experiment merely because a wording edit exists. Keep the baseline and criterion lineage intact; a comparative claim needs evidence, while a structurally admitted candidate without that evidence remains `behavioral_pending`. Human inspection can assess artifact quality; it does not replace independent comparative evidence or prove host consumption. Do not present source readback, lint scores, a smaller file, or a completed map as efficacy proof.
