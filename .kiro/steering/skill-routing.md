# Intent-first skill routing

## Scope and authority

Apply this pointer when selecting Core-Prompts skills in this repository, when
Core-Prompts is explicitly requested, or when a consumer project has opted in.
Do not replace an unrelated task's established workflow with a universal Core-first
route. Honor an explicit named skill or scoped direct request; report a material
mismatch rather than silently changing it.

Keep user, host, project and applicable home policies in force. Dotfiles owns
home-global policy. Skill selection grants no new execution, editing, delegation,
goal, installation, messaging, merge, release, publication or scheduling authority.
Proceed with already authorized work without re-asking permission merely because
a route was explained; preserve genuine approval and independent-review gates.

## Invoke intake when it is useful

For vague intent, a material ambiguity about the needed output or depth, uncertain
skill choice, or a continuation whose owner/relationship is unclear, select the
available `engos-orchestration-route-intent` skill. Read its complete effective
SKILL.md and selected resources, then follow its adaptive intake and conditional
relationship contract in the current assistant. Do not create a new agent to run
this skill or recursively route it through itself.

The method applies to every current catalog job, including nonengineering work,
without a fixed count, name list or domain filter. It uses actual context and
accepted artifacts, recommends a practical outcome and depth, and asks only
consequential unanswered questions. Every routing/intake question offers a free-text
Other path through an actually available question tool or an inline fallback.
Unknown, silence, a recommended option or a UI default is not an answer or approval.
Users need not name a framework to request a complete reviewed proposal workflow.

When any selected Core skill presents a question or choice to the user, preserve
a free-text Other/correction path, including during downstream work. A documented
native Other field satisfies this rule; otherwise offer the inline fallback. Do
not change a required approval mechanism or treat a suggested option as consent.

A clear direct task or already selected skill bypasses redundant routing intake.
Load the receiving skill's contract and proceed within existing authority. The
router is not a mandatory interview, an automatic full stack or a substitute for
the selected owner's required questions, artifacts, reviews and human decisions.

## Resolve actual availability and current relationships

Confirm the package available to this session; repository/catalog presence alone
is not native discovery. The routing skill's read-only inspector uses an explicit
trusted Core root to observe the current `.meta/capabilities/` inventory and its
bundled relationship table. Optional explicit package roots add observations, not
installation, trust or native-registration proof. A bundled snapshot is labelled
as fallback evidence, not a current inventory.

If the routing skill is unavailable, say so. Use a bounded manual inspection of
available skill entries to recommend a suitable first job when inputs suffice,
or report the specific missing package/root/context. Preserve the same authority,
Other/free-text and unknown-evidence boundaries; do not pretend the skill ran,
automatically install it, create a replacement agent or guess a workflow.

The selected skill's full current contract governs its behavior. Curated sequence,
iterate, return, parallel and support links are conditional suggestions, not
permissions or dispatches. Stale/missing relationships remain untrusted but do not
exclude valid updated/new skills. Do not infer safe parallelism from graph shape
or empty planning write sets; actual dependency, write, independence and authority
checks remain with the responsible host/execution owner.

## Adoption and evidence

The root AGENTS pointer applies in the Core-Prompts context; documentation or a
visual guide does not register global harness routing. A consumer project can
explicitly load this pointer and the available routing skill through its supported
instruction mechanism. Keep the trusted Core root separate from the user's project.
Verified runtime use does not require source-only human docs, the source job map,
UAC or source-maintenance prerequisites.

The compact [runtime guide data](intent-routing.json) and the source
[route catalog](../../.meta/intent-routing.json) support the portable guide; they
are not a semantic classifier or a complete current-catalog substitute. Checked
boxes and guided answers are user-supplied context, not independently verified
acceptance or completion. The routing skill owns the adaptive method and current
inventory/relationship interpretation.

Kiro documents workspace steering and always-included AGENTS.md, while custom
agents require explicit steering resources. File presence does not prove that a
particular custom agent loaded this pointer. See
[official Kiro steering documentation](https://kiro.dev/docs/steering/).
Do not change home/provider configuration or activate hosting as an intake shortcut.
Report static consistency, effective loading, observed behavior and measured routing
benefit separately; none is established merely by adding this pointer or guide.
